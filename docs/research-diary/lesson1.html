The confusion that started it

Seven months of building a machine that watches memory, and then a classifier that kept confusing workloads it should have separated easily. The turning point was refusing to tune the model and asking what the instrument was actually able to see.

The one idea to hold onto

The instrument records only writes. Everything confusing about the early results follows from that one sentence, and it took six months to take it seriously.

1
The primitive

What the machine actually writes down

Pause a virtual machine. Copy its entire physical memory to a file. Let it run for a moment. Copy it again. Now compare the two copies page by page — 4096 bytes at a time — and write down two numbers per page.

The first is the Hamming distance: how many individual bits flipped. The second is the cosine similarity between the two pages read as vectors of numbers: not how much changed, but in what direction. One page of memory, two numbers, repeated for every page, every snapshot, for the length of a run.

In plain terms

The machine takes two photographs of memory and describes the difference between them with two numbers per page: how much changed, and in which direction. Everything after this is an argument about what those numbers mean.

Where the first version came from

The repository opens on 4 November 2025 with a README that says the project is "used only for correctness validation — not full analysis, feature extraction, or modeling." Before asking what the signal meant, the question was whether the subtraction was even self-consistent: does comparing a page with itself give zero, does the comparison give the same answer in both directions, does a frozen machine produce a flat line.

2
The blind spot

A probe that read one byte for three months

Six workloads were written to act as known reference signals — three that stress memory, three that stress disk. One of them, mem_pointer_chase, was supposed to walk pseudo-randomly across a gigabyte of memory, producing a scattered, unstructured pattern to contrast against the neat sequential one.

Its loop computed the next position and then never moved to it:

// the next index is computed…
i = (a * x + c) % m
// …and then the OLD one is used. x is never assigned i.
idx = x * stride
acc ^= arr[idx]

For 300 seconds per run, the "random walk over a gigabyte" read the same single byte, over and over. It was written on 16 January 2026 and fixed on 20 April — three months later, and after the entire 48-recording campaign that produced the results in this entry.

And the fix did not make it a good probe, because of the sentence that governs the whole project:

Takeaway

A page contributes to the signal only when its bytes change. Reading produces nothing. mem_pointer_chase only ever reads — so even working perfectly, it is invisible to the instrument.

The audit that established this put it flatly: rewriting the workload in C "makes the invisible workload faster but not observable." The class that was supposed to anchor one end of the memory family was contributing a flat line, and its label was still pulling the family's centre of gravity around.

Be honest about the limits

This is a permanent property of the method, not a bug that got fixed. Any workload whose signature is mostly reads — a cache-resident scan, a compute kernel that streams from a table it never writes — is close to invisible here. Later entries return to this as a designed-in control rather than a flaw.

3
The contaminated baseline

Idle is never idle

The experiment ran workloads in cycles with 60 seconds of idle between them, and recorded the idle stretches too — 24 of them — as a baseline for "nothing is happening."

They were the least consistent class in the entire dataset. Run-to-run variation for idle came out at 0.973, against 0.048 for the most stable workload. One coherence measure ranged 135-fold across idle recordings alone.

io_many_files0.048very stable

The reason is obvious once stated. Sixty seconds after a workload stops, the operating system is still writing back dirty pages, still reclaiming caches, still holding a gigabyte of buffer mapped. Each idle window was measuring the residue of whatever ran before it — a different residue every time.

Analogy

Trying to record silence in a room where someone has just stopped talking. What you capture is the reverberation, and it differs depending on what was said.

Where this earns its keep

The two earliest idle recordings in the campaign sat inside the active workloads' territory geometrically. That is not noise — it is the instrument correctly reporting that the machine was still busy. The verdict was that idle is a protocol problem, not a code problem: drop caches first, extend the gap, and record which workload preceded each idle.

4
The reframe

The confusion matrix is a map, not a scorecard

With four runs of each of six workloads, the classifier's results split cleanly in two. Telling active from idle worked: 32 of 41 measures separated them significantly. Telling memory from disk collapsed entirely — the two families' centres sat 0.301 apart while the spread within each family was 1.846 and 1.594. The memory class scored a negative cohesion value, meaning its recordings sat geometrically inside the disk cluster.

mem_alloc_touch_pages  4/4
io_many_files          4/4
io_seq_fsync           4/4
mem_pointer_chase      3/4   → mem_stream
io_rand_rw             3/4   → mem_alloc_touch_pages
mem_stream             2/4   → run_idle, → io_rand_rw

The decisive move was to stop reading this as an accuracy table. Two long documents written on 10 May 2026 reframed it as a diagnostic map of behavioural overlap, hidden side effects, test impurity, and metric limitations — and imposed a rule that every off-diagonal cell must be attributed to one of four causes before any conclusion is drawn:

Cause 1

Real overlap

The two workloads genuinely do similar things to memory.

Cause 2

Capture artifact

The instrument, the runtime, or the kernel introduced it.

Cause 3

Order contamination

What ran before this recording leaked into it.

Cause 4

Metric inadequacy

The measurement cannot express the difference, even though it exists.

The rule

Overlap is last

Claiming real behavioural overlap is only defensible once the other three are ruled unlikely.

The rule

Direction matters

Always "true → predicted", never "A confuses with B" — the two directions have different mechanisms.

Order contamination was not hypothetical. One workload's coherence measure decayed monotonically across the four cycles of the campaign — 0.483, 0.345, 0.134, 0.133 — a fingerprint of position in the run rather than of the workload itself.

confusion_matrix_diagnostic_methodology.md · 2026-05-10 · 798 lines

"A workload label should be treated as the intended stimulus, not as a guarantee that the observed memory signal is pure."

This is the sentence the rest of the project is built on. Everything from here is an effort to make the observed signal closer to the intended stimulus — and to be explicit about the remaining gap.

How to test

The same document requires every future workload spec to pre-register its expected confusions — write down, before capture, which other workloads you think it will be mistaken for. Entry 10 shows this idea grown to its full size, applied to a hundred workloads at once.

5
The quiet loss

Half the signal was going in the bin

The measurement produces two channels — magnitude and direction — and the design combines them into one complex number. On 20 April 2026 it emerged that the pipeline had not been doing that for months.

The engine faithfully wrote both channels to disk from day one. The consumer that assembled them into an analysable matrix appended only the cosine channel. And the loader then cast the result to a plain floating-point type, which discards a complex number's phase entirely. Every synchrony and stability measure computed up to that point had been running on half the data.

Where this earns its keep

The response was not to discard the earlier results. It was to write the constraint into three documents and into a comment beside the offending line, along with a standing rule: reported results must explicitly state which path was used. The stated reason — "prevents future overclaiming" — and the honest reading: cosine-only separability is a real baseline result, not a failure.

The repair, two weeks later, was only possible by luck. The raw memory dumps were long deleted; the rotated per-channel text files had survived. A rebuild tool reconstructed every matrix from those, pairing the two channels by the timestamp in their filenames.

Be honest about the limits

Nothing in the design guaranteed that recovery. It worked because an intermediate artifact happened to still be on disk. That is not a reproducibility practice — it is a near miss, and it is part of why later entries treat raw retention as a first-class problem rather than an afterthought.

The same April week produced the other reason the pipeline could not be trusted yet: it was being asked to sample roughly 600 times faster than it could actually serve. The configuration requested ten samples per second; the measured time to process one pair was 57 to 68 seconds. The engine was allocating around a million short-lived buffers per job, running sixteen redundant async runtimes, and funnelling all of its parallel reads through a single lock. After the rewrite: thirty-two allocations, no async runtime, and lock-free reads — with the output verified bit-for-bit identical.

The line worth keeping

From the throughput analysis, on the temptation to raise the queue limit and make the backlog warning go away: "It does not increase throughput; it only delays the visible backpressure signal while accumulating more RAW files."

6
The discipline

Refusing the easy sample size

The campaign had 48 recordings. Four per workload is a thin basis for any claim, and there was an obvious way to make the number bigger: each run is a time series, so cut every run into segments and count each segment as a sample. Forty-eight becomes one hundred and ninety-two.

The plan written to introduce segmentation forbids this, in its own first section:

segment_level_analysis_critique_and_plan.md · 2026-05-10

Segment-level analysis is "scientifically valid as a within-run diagnostic tool. It is not valid as a sample-size inflation tool." Converting k segments × 48 runs into "192 samples" for any inferential test is explicitly prohibited.

Segments from one run are not independent observations — they share the run's machine, its moment, and its drift. Counting them as separate samples would have made every significance test look far better than the evidence supports.

The prohibition was then copied into the command-line help text of the tool that performs the segmentation, so that a future user — including a future version of the author — could not do it by accident.

Takeaway

The most reusable habit established in this period is not a technique. It is writing the argument against your own convenience down, in the place where the temptation will actually occur.

By 18 May 2026 the workloads were rebuilt — eighteen of them, mostly in C, each designed to isolate a single mechanism, with a safety model capping files, bytes and runtime before the first byte is touched. The build passed 52 of 52 smoke checks.

Be honest about the limits

That smoke run was executed on a Mac, and the document says so: it validates that everything builds, not that it behaves. The three features most likely to matter for a memory experiment — pinning a process to a CPU, suppressing huge pages, and pre-faulting memory — are precisely the three that do nothing on macOS and could not be tested there.

Everything was now in place: workloads that write, a metric that records, a pipeline fast enough to keep up, and a diagnostic framework for reading the results. The next question was whether the instrument was telling the truth about time. It was not.

Glossary

Hover any dotted term for its definition.

Page
The 4096-byte unit the operating system moves memory around in. The instrument compares memory one page at a time, so a change of one byte and a change of all 4096 both register as "this page moved".
Hamming distance
The count of individual bits that differ between two blocks of the same size. Here it measures how much of a page was rewritten between two snapshots.
