Plan 05 · snap-throughput lift · v1 proposal

Stop tuning the interval.
Shrink the snapshot.

Plan 02 proved the requested sampling interval is inert: the guest idles its requested ~0.52 s while the host snapshot cycle runs an order of magnitude longer. The v3 timing audit then localized the cost: pmemsave is a median 7.06 s, about 81% of the 9.75 s median cycle (range 2–24 s). The cadence that governs every trajectory length is set by one full-RAM dump, not by any knob we have been turning. Plan 05 attacks that dump directly with a factorial of capture-side levers — guest-RAM size, dump-target filesystem, and the delete-as-you-go path — guarded by an APF-fidelity gate so a cheaper snapshot still measures the same signal. No analyzer changes. The Tier-2, capture-semantics-changing levers (dirty-bit incremental capture, multifd, compression) are deliberately scoped to a separate track.

SECTION 01

Executive summary

Outcome (Wave 2, 72-run pilot). Run at 1024 MiB, SSD vs tmpfs × keep vs self-clean. The throughput gate “failed” across the board — but the chase for why overturned the reading. The old 7.06 s was not the dump's true cost; it was the median of a right-skewed spread (0.76 / 7.06 / 21.57 s) inflated by never deleting dumps (keep_dumps=true on 125/128 cells). The pilot streamed-and-deleted on every arm, so all four sat at the 0.79 s floor and the gate — comparing already-fixed arms — saw no gap. The real win is delete-as-you-go: 7.06 s→0.79 s and snapshots 14→79 per 120 s (~5–8×). The disk gate passed (peak ≤3 GiB, via the new sudo-delete fix); fidelity recalibrated to an effect-size KS (9/18 pass), with the residual failures traced to near-idle APF — the Wave 3 probe found the workloads (app_hashtable, sandbox_scanner) treat --duration as a cap and exit in 1–2 s, so the guest idles most of the window (not a delete race). Full reasoning: The 7-second mystery. The text below is the original pre-pilot proposal, kept for the record.
What Plan 05 is

A capture-side throughput experiment. Hold the analyzer fixed (Plan 03 W=8, H=4; Plan 04 segmenter) and sweep the variables that actually move pmemsave: guest RAM size {1024, 512, 256} MiB, dump target {SSD, tmpfs}, and keep_dumps {true, false}. Measure the per-phase timing already emitted by the instrumented producer (mean_pmemsave_sec, mean_host_snapshot_cycle_sec, pause fraction) and, for every fast-arm cell, verify the resulting APF trajectory is statistically indistinguishable from the 1024 MiB/SSD baseline on the same workload. Output: plan05_throughput.csv, plan05_summary.json, a new validator claim C9, and the first measured delete-as-you-go peak-disk number.

What changes vs the naive baseline
  • Δ-1 · target pmemsave, not the interval — the interval is proven inert (Plan 02), so it is held fixed
  • Δ-2 · factorial RAM × target × keep_dumps, not a one-variable sweep
  • Δ-3 · add an APF-fidelity gate: a faster dump must reproduce the baseline APF distribution, else it is measuring a different signal
  • Δ-4 · scale working-set with RAM (or exclude mem_workingset_sweep_v2 from the sub-1024 arm) to avoid the binding-constraint confound
  • Δ-5 · validate delete-as-you-go (keep_dumps=false) peak transient disk in the same campaign — closes round-2 finding R-3
  • Δ-6 · scope out Tier-2 (dirty-bit / multifd / compression) to a follow-up: they change capture semantics or the novelty claim (see §07 dispute 3)
Net effect. Plan 05 is a capture re-run, not new analysis code. Reusing run_timing_instrumentation_experiment.py --ram-mb and the existing producer_stats schema, it adds a fidelity comparator (~120 LOC) and one validator claim. If the reduced-RAM arm holds, it both halves the cadence bottleneck and retires two round-2 open items at once (the storage-ratio numerator and the delete-as-you-go cap).
Bound surfaced. The headline risk is not speed but meaning. Shrinking guest RAM changes how much memory a workload can touch; a 256 MiB mem_workingset_sweep_v2 is a different experiment, not a faster one. Plan 05 therefore cannot report a pmemsave speedup without simultaneously proving the APF signal is preserved — the fidelity gate (Δ-3) is a first-class acceptance condition, not a footnote.

SECTION 03

Baseline · the design doc as written

What docs/tuning_plans/02_interval_tuning_experiment.md sketched

A factorial pilot over interval, guest RAM, and the dirty-page flush, intended to find a faster sampling configuration. The original framing still treated the interval as a primary knob and RAM as one secondary axis among several. The SNAPSHOT_INTERVAL_TUNING_STUDY later identified reduced guest RAM as “the structural lever for ‘experiment feels slow’” (a 512 or 256 MiB VM cuts dump time roughly in half or a quarter), but no campaign has yet swept it.

The naive spec, and why it is not enough
  • Independent variables: interval_ms, ram_mb, flush on/off
  • Metric: mean_pmemsave_sec, mean_host_snapshot_cycle_sec
  • flaw the interval is inert — sweeping it wastes the budget
  • flaw RAM reduction is confounded with workload behavior; no fidelity check
  • flaw no tmpfs arm, though the dump target is the actual write path
  • flaw delete-as-you-go (the disk-cap claim) is never validated
Anchor. The cost mechanism is settled: pmemsave is a synchronous full-RAM serialization — a flat RAW file of size ramSizeMb, a single ~1 GiB sequential write to /var/lib/libvirt/qemu/dump on SSD. At ~1.36 GiB/s on a quiet host this is ~0.76 s; under I/O contention bandwidth drops to 0.27–0.71 GiB/s, and as dirty pages accumulate without a flush the dump drifts from 0.78 s toward 7.25 s. Plan 05's job is to make that write cheaper or move it off the SSD, not to sample more often.
SECTION 04

Top-down analysis · pipeline level

Process model · where the cost lives

host snapshot cycle (Axis B, median 9.75 s)   |   +-- suspend ......... ~0.35 s (negligible)   +-- pmemsave (full-RAM RAW dump) ... ~7.06 s <== 81% OF CYCLE   +-- resume .......... ~0.05 s (negligible)   +-- guest run ....... ~0.52 s (the "interval" -- inert)   |   +~~ async APF helper (B+3.1) ... ~1 s, OFF critical path       memmap XOR -> append jsonl -> delete prev.raw -> .apf_done ack Plan 05 target: the one red line. Levers either shrink the bytes (reduce RAM) or move the write off the SSD (tmpfs), holding APF fixed.

Objective alignment

Cadence is not a comfort metric; it sets the science. pmemsave dominance means trajectory length is governed by the dump cost, and trajectory length is exactly what starves the analyzer: 53 of 132 v3 cells yield ≤3 analysis windows at (8,4), which is what makes gate G2 (spectral coverage) fail for the phasic family and G3 (cepstral-SNR) fragile. Halving pmemsave roughly doubles the snapshot count at fixed wall-clock, directly feeding G2/G3 degrees of freedom. The lever and the analyzer's open problems are the same lever.

Scope boundary

Plan 05 is capture-side only. The APF definition, the window/hop grid, the gates, the classifier, and the segmenter are all frozen. The single new analysis artifact is a comparator that asks “is the fast-arm APF the same distribution as the baseline APF?” Anything that changes what a snapshot contains (incremental/dirty-bit capture) is out of scope by construction — see dispute 3.

Structural risks

  • Semantic drift. RAM size and dump target must not change the APF a workload produces. This is the load-bearing risk and the reason for the fidelity gate.
  • Host-state confound. pmemsave is non-stationary under I/O contention; before/after arms must run on a quiescent host with randomized arm order.
  • tmpfs pressure. A RAM-backed dump target competes with guest RAM and page cache; only safe with delete-as-you-go bounding the live dump count.

SECTION 07

Key disputes + decisions

Dispute 1 · Does reduced RAM preserve the signal?

Tension. Reducing guest RAM linearly shrinks the dump (the whole point) but also shrinks how much memory a workload can dirty. Decision. RAM reduction is admitted only behind the APF-fidelity gate (Δ-3): a fast arm passes only if its APF trajectory is statistically equivalent (TOST) to the 1024 MiB baseline on the same workload. A speedup without equivalence is recorded as a different experiment, not a win.

Dispute 2 · Working-set workloads have a RAM floor

Tension. mem_workingset_sweep_v2 and the mmap sweep need ~1 GiB to exhibit their behavior. Decision. Two-track: scale --working-set-mb with ram_mb where the workload supports it (preserving the fraction of RAM touched), and exclude workloads that cannot scale from the sub-1024 arm rather than reporting a confounded number.

Dispute 3 · Dirty-bit incremental capture — the big lever we will not pull (yet)

Tension. APF needs only the changed pages, and QEMU's migration dirty-bitmap could dump just those — potentially the largest speedup on the table, since APF means are ~0.13–0.20. But Paper A's novelty is that APF is content-derived (a byte difference) and capture-external, positioned explicitly against hardware dirty-bit estimators. Building APF on the dirty bitmap collapses that distinction. Decision. Scope dirty-bit capture out of Plan 05 into a separate Plan 05b, framed honestly as a different method with a different novelty claim. This is the one partial vote.

Dispute 4 · Compression / multifd

Tension. Compression trades CPU for write bytes (sparse low-APF dumps compress well); multifd parallelizes the write. Decision. Both put work on or near the critical path and need a migrate “file:” target rather than pmemsave — an architecture change. Defer to Tier-2; Plan 05 keeps the pmemsave primitive.

Dispute 5 · Validate the disk cap now or never

Decision. Unanimous: include the keep_dumps=false arm. It is nearly free (the delete branch already exists) and it closes round-2 R-3 — the 2–3 GiB streaming cap that v3 never exercised — and supplies the measured numerator the storage-reduction claim currently lacks.

Dispute 6 · Matrix cost

Decision. A full 11×3×3×2×4 grid is wasteful. Run a representative subset: 3 workloads (one steady high-APF, one phasic, one RAM-floor case), 2 durations (120/600 s), the RAM×target×keep_dumps cells, 3 replicates. Expand only if the pilot shows a fidelity-preserving win.

Decision rule

A (ram_mb, target) configuration is recommended for a workload iff it passes G-T1 and G-T2. tmpfs configurations additionally require G-T3. A speedup that fails G-T2 is reported as a semantic-drift finding, not a recommendation.

SECTION 09

Validation strategy

New operational claim · C9

C9. “There exists a capture configuration that reduces median pmemsave by ≥2× while preserving APF fidelity (G-T2) on at least the steady high-APF and phasic representatives.” C9 is operational: it gates whether a faster cadence is available for a future full re-capture, not whether any scientific result changes.

PASS condition

C9 passes iff ≥2 of the 3 pilot workloads have a configuration clearing G-T1 and G-T2, and the tmpfs arm clears G-T3. A fidelity-preserving win on the RAM-floor workload is a bonus, not required.

Sub-pilot vs full sweep

Sub-pilot first: one workload (rmw_intensity), 256 vs 1024 MiB, SSD, keep_dumps=true, 3 replicates — a 6-cell smoke test that the fidelity comparator works and the speedup is real before spending the full matrix.

Fidelity test fixtures

Reuse a known-stationary steady cell as a positive control (baseline vs baseline replicate must pass equivalence) and a deliberately RAM-starved cell as a negative control (must fail equivalence), so the gate's sensitivity is itself validated.

Failure-mode handling

If no arm passes G-T2, Plan 05's deliverable is the negative result — “pmemsave cannot be cheapened without changing the signal at this RAM range” — which itself justifies the Tier-2 (dirty-bit) follow-up.

SECTION 10

Statistical design

Test framework

Paired before/after per workload: each fast arm is compared to its own 1024/SSD baseline at matched (workload, duration). Report the median pmemsave reduction with a grouped bootstrap CI over replicates, not a single ratio.

Equivalence, not difference

Fidelity (G-T2) uses a TOST (two one-sided tests) equivalence test on APF mean and std against a pre-registered margin, because the goal is to fail to reject difference is small — a plain t-test that fails to reject the null would wrongly reward an underpowered comparison.

Confound control

pmemsave is non-stationary under host I/O contention (Experiment 1 showed suspend/dump drift). Mitigations: quiescent host, randomized arm order within a replicate, and recording backpressure_events / queue_max_depth to flag any contaminated cell.

Sample size

3 replicates per cell for the pilot, sufficient for a 2× effect with low within-arm variance; escalate to leave-one-replicate-style CIs only if the effect is marginal (<1.5×).
