Plan 06 — Disk-I/O capture channel

A second capture channel, builds on Plan 05. Companion: Plan 05 overview.

The question

Plan 05 found one hard boundary: a single memory scalar (APF) cannot separate the stealth threat slowburn from the benign pagefault — they are twins in memory. What separates them is disk I/O (slowburn writes files; pagefault only faults RAM), which APF cannot see. Plan 06 adds a per-snapshot disk-I/O channel (host-side domblkstat at the memory-snapshot cadence) — additive and flag-gated (CAPTURE_DISKIO, default off = byte-identical).

Subset to validate: 8 workloads × 600 s × 2 reps = 16 cells, both threat families + the masquerade benigns.

Channel validation

Host domblkstat wr_bytes over a 600 s ransom_seq cell rose 6.5 MB → 11.3 GB, matching the guest's own /proc/diskstats (~7.8 GB). The channel captures guest disk writes correctly. (A 15 s batched smoke looked flat only because batched is the memory-capped workload that barely writes.)

The heaviest writer is benign (mmap_traversal, 140 MB/s — read-modify-write on a mapped file), and a threat writes nothing (batched, mem-capped). So "writes to disk" is a behavior, not a threat sign — exactly as APF was. Adding disk I/O did not lift threat/benign classification. (The 16-cell subset is below majority baseline anyway; the direct pair measurement is the trustworthy result.)

Full 66-cell run — characterization vs detection

Characterization: disk helps. Instance 0.924→0.939, seen-family 0.955→0.985, and novel-workload family 0.348→0.455 — crossing the 0.364 baseline that memory alone could not. The disk channel is what makes family generalize to an unseen workload.
Detection: disk hurts. LOWO 0.742→0.636, LOFO 0.576→0.424 — "writes to disk" is not a threat marker (benign mmap is the heaviest writer), so it adds a confounding axis.

The reframe

A second channel's value is behavioral disambiguation — separating workloads that alias in the first channel (slowburn ~ pagefault in memory, now split on disk) — not threat detection. No single channel is a threat marker; benign workloads sit at the loud end of both. This sharpens the stance: characterization, not detection. The defensible claim is "two orthogonal channels disambiguate behaviors that one channel aliases," not "the second channel catches the threat."
